RoleMatrix shows who writes, does and approves each document, like the signature blocks on a controlled document, so the split between our work and your sign-off is visible at a glance.

- Data: a `table` block with `"as": "roles"`. `cols`: document, then one column per role ("Written or done by", "Reviewed by"). A cell starting "Aquemi" is ours, "You" or "Your" is yours, anything else shared.
- Plate caption: "Aquemi · <nav> · N documents" by default. When the rows are not all documents, `caption_noun` names them, the router's count rule (`wCount` in `core.js`): `caption_noun`, else `fold_noun`, else "documents" (`"caption_noun": "requests"` reads "6 requests", for svc-upgrades' list where row 6 is a consultant); `"caption_noun": ""` drops the count. A block with neither field reads as before. The fold button ("Show all 7 documents") names the rows the same way: `fold_noun`, else `caption_noun`, else "documents".
- Markup (`blocks/roles.js`), on a Plate (`wPlate`: a `line` frame on `surface-raised`, caption Aquemi · nav · N documents, above): `.aq-roles` > `.aq-roles__key` (one plain line: `.aq-roles__keyk` "Key" as an `eyebrow`, then three sample parties) and `ol.aq-roles__rows` of `li.aq-roles__row`: `.aq-index`, `h3.aq-roles__t`, `.aq-roles__stamps` of `.aq-roles__cell` (`p.aq-roles__k` role label, `p.aq-roles__stamp.is-ours|is-yours|is-shared` the party). Each party is marked by a 2 px line on its left, no frames or fills: ours `flow`, yours `ink-muted`, shared a dashed `line-strong`.
- Each document is a row on a `line` hairline. Desktop: the shared mono index and the document (Geist 400 20/28) in the first columns, then one column per role: the role name (Geist 500 14/20 `ink-muted`) above the party (Geist 16/24). Phones: the document as the row's title (18/24), the role cells side by side under it (role 12/16, party 14/20).
- Ground: the section's `surface`, with the plate on `surface-raised`, in either theme. Keep each cell short; the party first ("Aquemi drafts…", "Your validation team").

## Motion

`motion.js`: the key's three stamps strike first, then each signature block rises into place and its stamps strike one after another, left to right, like a document being signed off. Blocks play in reading order as they scroll in. Nothing under reduced motion.
